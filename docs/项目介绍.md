# GitHub 热门项目排行榜 · 项目介绍

> 一句话：把 GitHub 上最火的开源项目整理成中文友好的排行榜——纯静态页面、零数据库、免费跑在 Cloudflare Workers 上。

- 源码仓库：<https://github.com/xiaoh2018/github-rank>

- 许可证：MIT

## 它能帮你做什么

**1. 追新——发现正在火起来的项目**

「近 7 天」榜单只收最近 7 天创建、星标数已超过 50 的仓库，配合作者榜和「新晋 / 掉队」变化榜，能第一时间看到哪些新项目在起飞。

**2. 纵览——四个视角看全貌**

近 7 天 / 近 30 天 / 近 1 年（按创建时间圈定「新项目」，再按星标排）/ 总榜（不分创建时间，GitHub 全站星标降序前 500，深翻 10 页抓取），每个榜单最多 500 个项目，可按语言（15 种）和 8 个内容分类（AI·LLM / 工具 / 前端 / 开发工具 / 安全 / 数据后端 / 游戏 / 学习资源）过滤。

**3. 深挖——点开就是项目档案**

点任意项目打开右侧抽屉：Star / Fork / 许可证 / 最近提交 / 最新 Release / 前 8 位贡献者 / README 全文（**直接渲染成排版后的 Markdown**：标题、表格、图片、代码块、任务清单都在，顶部另给「在 GitHub 看完整 README」的入口），中文译文一键切换。README 和简介都是机器翻译，有译文时会标注「机器翻译 · 仅供参考」，没到译文时不会显示任何「翻译中」的占位提示。

**4. 收藏与分析**

- 收藏保存在浏览器本地，可导出 / 导入 JSON 文件（换电脑不丢）
- 导出 CSV（Excel 直接打开，含星标增量列）
- 生成分享卡片图片（一键保存 PNG）
- 侧栏统计：项目数、星标总数、平均星标、最热语言、语言分布图、上榜最多的作者

**5. 中文搜索**

搜索支持中英文混合，常用中文词自动映射到英文主题（「命令行」→ cli、「前端」→ frontend 等 23 组同义词）。

## 还可以怎么用

- **安装成 App**：支持 PWA，手机浏览器「添加到主屏幕」后可离线打开（缓存机制：页面外壳离线可用，数据在线时更新）。
- **写文章**：站长可在后台发布 Markdown 文章（标题 / 列表 / 任务清单 / 表格 / 代码块 / 链接 / 图片），渲染前全量转义 HTML，不执行脚本。
- **当数据源**：`data/repos-meta.js`（元信息 + 开发者/组织榜）与 `data/repos-{week,month,year,all}.js` 是结构化数据（`window.__GHRANK_META__` / `window.__GHRANK_RANGES__`），可直接被其他脚本消费。

## 技术架构（一图流）

```
GitHub Search API
      │  每 3 小时（GitHub Action，cron 17 */3 * * *）
      ▼
 scripts/fetch.js（Node 20，无依赖）
      │  分段搜索 → 去重 → 翻译简介/README → 原子写文件
      ▼
 仓库 data/ 目录（repos-meta.js + repos-<range>.js/.json（页面用 JS、接口用 JSON）/ desc-zh.json / readme-zh.json / site.json / links.json / articles.json / nav.json / qa.json）
      │  raw.githubusercontent.com
      ▼  Worker 从 raw 读取并转发（边缘缓存 5 分钟）
 Cloudflare Worker（worker.js 单文件）
      │
      ├─ 静态站点：/、/articles、js、数据文件
      ├─ API（共 20 个）：
      │    榜单 /api/rank（range·limit·lang·topic·format=tsv）、站点 /api/site、/api/status、/api/health
      │    内容 /api/articles、/api/article、/api/nav、/api/qa、/api/links
      │    翻译 /api/desc-zh、/api/readme-zh、/api/translate、/api/ai-usage
      │    GitHub 代理 /api/gh、/api/gh-search、/api/refresh、/api/fetch-meta、/api/run
      │    运营 /api/submit、/api/index-check（收录自查与批量查）
      ├─ 后台：/admin（14 个标签页：概览 / 友链 / 广告 / 密钥 / 翻译 / 布局 / 联系 / 备案 / 导航 / 收录 / SEO / 问答 / 主题 / 文章，配置写回仓库 data/）
      └─ 定时保活：每周一 UTC 02:00 写 keepalive.txt
      ▼
 访客浏览器（js/bundle.js + sw.js）
      ├─ 默认用静态数据（零 API 请求）
      ├─ localStorage 缓存 2h + 收藏 + 趋势快照（对比 ≥1h 前算增量）
      └─ Service Worker 网络优先、失败回退缓存
```

翻译链路：仓库预翻译文件 → MyMemory（免 Key，每日 5 万字符额度）→ Workers AI（绑定即用）→ 全失败显示英文原文。

## 部署一个自己的排行榜

Fork 仓库 → 开 Action 写权限 → 建 fine-grained Token → 建 Cloudflare Worker 粘贴 `worker.js` → 配变量 → 手动跑一次 Action。完整步骤见仓库 [README.md](../README.md)「部署」一节，日常维护见 [docs/操作手册.md](操作手册.md)。

## 常见问题

**数据和 GitHub 实时同步吗？**
默认展示每 3 小时抓取的静态数据（不消耗任何 API 额度）；点「立即刷新」会实时拉取。

**为什么有的简介还是英文？**
机器翻译额度有限，按优先级逐步覆盖；额度恢复后会自动补翻。

**Token 填了会泄露吗？**
访客自己填的 Token 只存本机 localStorage，不上传；服务器 Token 只存在 Cloudflare Secret 里，代码仓库内无任何明文密钥。
